# دليل تنظيم المشروع

هذا الدليل يوضح مكان كل جزء وأوامر التشغيل والمراجعة. تنظيم الملفات يحافظ على روابط الموقع وقاعدة البيانات الحالية؛ تجهيز السحابة له مرحلة منفصلة قبل النشر.

## خريطة المجلدات

```text
src/
  app/                 صفحات Next.js ومسارات HTTP كما هي
  components/          مكونات الواجهة مجمعة حسب الاستخدام
    common/            الهوية والتنقل والثيم والعناصر المشتركة
    catalog/           كروت المدرسين والكورسات والفلاتر والصور
    admin/             لوحة الإدارة ومحررات المحتوى
    auth/              الدخول والتسجيل واستعادة الحساب
    enrollments/       تفعيل الاشتراكات
    learning/          مشغل الدرس
    assessments/       حل الواجب والامتحان
  server/              منطق الخادم والصلاحيات والتعامل مع البيانات
    core/              قاعدة البيانات والتشفير والأخطاء وHTTP
    auth/              الحسابات وخدمة الهوية والاستعادة وإدارة الطلاب
    catalog/           استعلامات المحتوى والإدارة والحذف
    enrollments/       الأكواد والاشتراكات
    assessments/       التقييمات والمحاولات والإدارة
    learning/          التقدم وصلاحيات التعلم
    media/             الصور والفيديو المحلي
    jobs/              العامل المحلي والمهام الدورية
  lib/                 التعريفات والقيم المشتركة وبيانات العرض
  fonts/               الخطوط المحلية وتراخيصها ومصدرها
scripts/
  local/               تشغيل الخدمات المحلية وإعدادها وتجهيز بيانات العرض
  verification/        فحوص الوظائف عبر HTTP وقاعدة البيانات
  deployment/          تجهيز ملفات العرض السحابي دون نقل قاعدة الجهاز
  shared/              تحديد مسارات المشروع وواجهة الخدمات المحلية
public/                الملفات العامة المسموح بعرضها للجميع
supabase/
  migrations/          تاريخ تغييرات قاعدة البيانات بالترتيب
experiments/           التجارب المرجعية وبيئة Supabase المحلية القائمة
docs/                  قرارات المنتج ونتائج المراجعة وتعليمات التشغيل
design-system/         المرجع البصري والتصميم المعتمد
.agents/               أدوات ومراجع مساعد التطوير
.local/                بيانات محلية وتقارير وصور وأسرار مستبعدة من Git
```

ملفات Next.js وTypeScript وESLint والحزم تبقى في الجذر، لأن أدوات البناء تتوقعها هناك. ملفات `page.tsx` و`layout.tsx` و`route.ts` داخل `src/app` تحدد روابط الموقع؛ تغيير ترتيب المكونات أو خدمات الخادم لا يغير تلك الروابط.

## التشغيل والتهيئة

نفّذ أوامر npm من جذر المشروع. تشغيل Supabase المحلي يحتاج Windows وDocker Desktop وCLI المثبت داخل تجربة Auth القائمة:

```powershell
npm run local:start
npm run dev
```

الأمر `local:start` يمرر خيارات التشغيل الحالية إلى المشغل الأصلي داخل `experiments/auth-spike`. لا ينقل مجلد Supabase ولا يعيد إنشاء قاعدة البيانات ولا يغير أسماء حاوياتها.

| الأمر                 | وظيفته                                                               |
| --------------------- | -------------------------------------------------------------------- |
| `npm run local:setup` | تطبيق migrations المحلية والتحقق من بصماتها دون إعادة تهيئة البيانات |
| `npm run local:seed`  | تجهيز الكتالوج التجريبي عندما تكون القاعدة فارغة                     |
| `npm run local:admin` | تجهيز حساب الأدمن المحلي دون طباعة كلمة السر                         |
| `npm run local:video` | تجهيز فيديو العرض الخاص عند عدم وجوده                                |
| `npm run local:demo`  | تجهيز ونشر دروس العرض التجريبية الثمانية عبر عمليات الإدارة          |

`scripts/shared/paths.mjs` يحسب جذر المشروع من موقعه، لذلك قراءة ملفات البيئة والتقارير لا تعتمد على المجلد الذي استُدعي منه ملف JavaScript. `scripts/shared/local-stack.mjs` يتيح الوصول للخدمات المحلية القائمة دون نسخ وظائف التجربة أو تغيير مسارها.

## المراجعة قبل تسليم تعديل

```powershell
npm run lint
npm run typecheck
npm run format:check
npm run build
```

ESLint يشمل `src` و`scripts` والإعدادات، ويتوقف عند التحذيرات. فحص التنسيق يقرأ الملفات دون تعديلها؛ `npm run format` يصلح تنسيقها. أوقف التطوير قبل البناء ثم شغّل `npm start` لتجربة النسخة المبنية؛ لا تشغّل خادمين على المنفذ 3000.

| المجموعة                                      | الأمر                        | المتطلبات                                                                                                                                   |
| --------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| الحسابات والأكواد والتعلم والاستعادة والإدارة | `npm run test:local`         | الخادم والخدمات المحلية وحساب الأدمن وكتالوج العرض الأساسي وصف `g3` وملف الفيديو التجريبي؛ ترتيب الفحوص محفوظ لأنها تشارك بعض حسابات التحقق |
| الصور والحذف والتقييمات المستقلة              | `npm run test:features`      | الخادم المحلي وحساب الأدمن؛ 40 فحصًا من المرحلة السابقة ببيانات تحقق تخصها                                                                  |
| إعداد اتصال السحابة ومفاتيح Auth              | `npm run test:config`        | Node 22؛ 10 حالات بإعدادات وهمية وHTTP/PostgreSQL loopback، دون قراءة env أو الاتصال بالسحابة                                               |
| تخزين الصور الدائم                            | `npm run test:image-storage` | Node 22؛ 11 حالة بملفات مؤقتة وHTTP loopback، دون bucket سحابية                                                                             |
| مدخل تسليم الامتحانات                         | `npm run test:deadline-job`  | Node 22؛ 9 حالات لعقد المسار مع runner وهمي، لا تفعّل جدولة                                                                                 |

تشغيل الفحوص ينشئ بيانات اختبار ويحفظ تاريخها وتقاريرها داخل `.local`. هذه أوامر تحقق محلية، وليست أوامر لترحيل بيانات الإنتاج أو حذف بيانات المستخدمين.

اختبار الأكواد يجهز مادة ومدرسًا وكورسًا مستقلًا لكل جولة، بروابط تحتوي UUID، وينشر درسًا بفيديو وواجب عبر عمليات الأدمن نفسها. لا يحتاج نشر كورس العرض `physics-electricity` ولا يعدّل محتواه؛ يستخدم صف `g3` الموجود فقط. ينقل المحتوى الذي أنشأته الجولة إلى المحذوفات عند الانتهاء أو الفشل، مع حفظ تاريخ التفعيل. بيانات كتالوج العرض تبقى مطلوبة لبعض فحوص التعلم الأخرى، وليس شرطًا أن تكون منشورة.

## قواعد إضافة الملفات

- الصفحة ومسار HTTP ينسقان الطلب والاستجابة، ومنطق الميزة في مجلدها داخل `server`.
- المكون المتخصص يبقى في مجلد ميزته؛ العنصر المستخدم في أكثر من قسم يمكن وضعه في `common`.
- أسرار الخادم لا تستوردها مكونات المتصفح. لا تُحفظ كلمات السر أو المفاتيح في ملفات التوثيق.
- تغيير قاعدة البيانات ينشئ migration جديدة؛ لا يُعاد كتابة ملف طُبق سابقًا.
- أدوات التشغيل المحلي داخل `scripts/local` والفحوص داخل `scripts/verification`، مع مسارات ملفات مشتركة من `scripts/shared`.
- ملفات `experiments` وقرارات المراحل ومراجع Figma محفوظة للمراجعة؛ النقل الحالي لا يمحو تاريخ العمل.

## الملفات المستبعدة من Git

`.env.local` و`.local` و`node_modules` و`.next` وتقارير التشغيل والذاكرة المؤقتة لا تدخل المستودع. كذلك إعدادات الربط المحلية لـNetlify وVercel وملفات Supabase المؤقتة ومفاتيح التوقيع المحلية مستبعدة. ملف `.env.example` يحتوي أسماء المتغيرات والقيم التجريبية فقط.

ملف `supabase/.temp/cli-latest` مولد بواسطة CLI؛ أُزيل من فهرس Git مع إبقاء النسخة المحلية. لا يدخل المشروع اعتماد خط Noto غير المستخدم؛ الخط الحالي Cairo محلي، وتراخيص الخطوط وملفاتها التاريخية محفوظة.

تفاصيل حركات الملفات في [سجل التنظيم](file-reorganization.ar.md). تعليمات إعداد نسخة جديدة ومتطلبات الانتقال للسحابة في [الدليل الرئيسي](../../README.ar.md).
