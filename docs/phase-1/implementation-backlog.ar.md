# خطة التنفيذ — المراحل 2–8

الخطة أُعدت عند تسليم المرحلة الأولى بعد اعتماد سلوك المنتج. تحديث 2026-10-02: نُفذت تجارب F01 محليًا، وأُعدت [مواصفة F02 للحالات](../phase-2/F02-state-contract.ar.md) مع [أمثلة الانتقالات](../phase-2/F02-transition-examples.ar.md) وقرار D28، ثم [تصميم F03 للبيانات](../phase-2/F03-data-model.ar.md) مع SQL مسودة و42 مجموعة تحقق، ثم [عقد صلاحيات F04](../phase-2/F04-permission-contract.ar.md) مع 48 عملية وguards و24 مجموعة تحقق في قاعدة ودور مؤقتين منفصلين. إعداد الاستضافة والتحقق الإنتاجي لـF01 مؤجلان إلى ما قبل الإتاحة الحقيقية، مع إبقاء أساس الصلاحيات أثناء البناء وفق توجيه المستخدم. [حالة المرحلة الثانية](../phase-2/README.ar.md) تحدد ما أُنجز؛ لا تطبيق إنتاج أو migrations نهائية حتى الآن. ثم أُنجزت [F05 للفرونت المحلي](../phase-2/F05-local-frontend.ar.md) بواجهة عربية وبيانات تجريبية وفحوص بناء و23 حالة HTTP و30 حالة عرض ناجحة. تحديث 2026-10-03: اكتمل الربط المحلي للحسابات وعمليات الأدمن والأكواد والدراسة والتقييمات والاستعادة، وفق موافقة المالك على مواصلة الدفعات المحلية دون توقف. [تقرير التطبيق العامل](../phase-2/F06-F12-local-platform.ar.md) يوضح الاختبارات وحدود التسليم؛ إعداد الإطلاق وربط الفيديو الفعلي ما زالا مؤجلين.

ترتيب المراحل التالي لتنظيم الاعتماديات، وليس وعدًا بمدة أو ميزانية. [القبول](acceptance-criteria.ar.md) و[القرارات](decisions.ar.md) مرجع كل مهمة؛ اختيارات التقنية والتفاصيل الموسومة كمقترحات تُراجع قبل المرحلة المعنية. يجوز إعداد عقد الحالات ومخطط البيانات المستقل عن المزود اعتمادًا على نتائج التجربة المحلية؛ لا يعني ذلك قبول إعداد Auth الإنتاجي قبل فحصه.

اختبار منطق التفعيل والمشاهدة في المراحل 5–6 يستخدم فيديو محليًا صالحًا للتجربة ومحاكي مزود؛ بيانات الدروس تحفظ هويات ثابتة دون أسرار. تعمل الحسابات والأكواد والتقييمات بمنطق خادم حقيقي في النسخة المعروضة قبل الدفع. لا تنشأ حسابات أو تجارب Bunny أو طلبات إلى API أثناء هذا المسار. ربطها الفعلي في 8.4، ثم اختبار حماية البث وأدائه في 8.5. لا بيع حقيقي قبل اجتياز بوابات المرحلة 8.

قيود لازمة: رقم طالب موحد فريد، سر كود فريد، تفعيل واحد للكود، محاولة فعالة واحدة لنفس الطالب/التقييم كاختيار تنفيذ مقترح، تسليم نهائي واحد، تحديث الوصول دون فقد التزامن. جميع المواعيد تحفظ كوقت مطلق وتعرض بالقاهرة. الطالب لا يكتب درجاته أو نهاية وصوله أو مفتاح الصحيح. رفض API مطلوب إلى جانب صلاحيات قاعدة البيانات. تاريخ التقييم محفوظ بإصدار المحاولة؛ المنهج يسمح بإضافة دروس دون إنشاء اشتراك جديد أو تجميد نسخة كاملة لكل طالب.

ترتيب فحص الصلاحيات: هوية صحيحة وحساب نشط أولًا؛ ثم دور أدمن أو ملكية الطالب للبيانات. القراءة التاريخية للنتائج والتقدم لا تتطلب وصولًا ساريًا D09. المحتوى وتشغيل الفيديو يحتاجان كورسًا منشورًا أو مؤرشفًا بوصول سابق صالح، ودرسًا منشورًا مفتوحًا. استئناف الامتحان بعد انتهاء الوصول استثناء للمحاولة التي بدأت بوصول صالح فقط وفق D10، ولا يتجاوز تعطيل الحساب D18.

Supabase اختيار المستخدم المبدئي D20؛ Next.js/Vercel مرشحان D21؛ Bunny Stream اختيار مؤكد D27 وتشغيلها الفعلي مؤجل لنهاية التجهيز. توافق تسجيل الهاتف بكلمة سر دون SMS يحتاج تحققًا تقنيًا؛ لا يفترض أن تعطيل تحقق الهاتف وحده يحقق المتطلب بأمان. لم تتضمن مرحلة المواصفات الأولى SQL أو إعداد خدمة؛ تجارب F01 وSQL مسودة F03 المحليتان موثقتان في المرحلة الثانية، وليستا إعداد إنتاج معتمدًا.

مراجعة التكلفة قبل أي اشتراك: تخزين ومشاهدة الفيديو، قاعدة البيانات/Auth والنسخ الاحتياطي، استضافة التطبيق ونقل البيانات، دومين، بريد تشغيلي إن لزم، SMS فقط إن تغير القرار، مراقبة مدفوعة إن لزمت. لا خدمة مدفوعة معتمدة هنا. الأسعار المرجعية للفيديو أدناه لا تمثل تصريحًا بالاشتراك؛ تُراجع ثانية مع توقعات الطلاب والمشاهدة عند 8.4.
