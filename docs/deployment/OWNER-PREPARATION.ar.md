# إيه اللي باقي علشان نسخة العرض تشتغل أونلاين؟

آخر مراجعة: ٤ أكتوبر ٢٠٢٦.

مشروع Supabase المقصود اتحدد واتجهز بالفعل: **mnsaaa**، ورقم المشروع `soggnbfxawlwopglghas`. اتطبقت migrations الأربع بعد موافقتك، واتضاف الكتالوج التجريبي واتراجعت أعداده. التصميم اللي اعتمدته اتطبق في الموقع واتراجع محليًا على الكمبيوتر والموبايل، مع البحث والفلاتر والدارك مود. لوحة الأدمن محتفظة بشكلها المعتمد.

رابط Netlify اللي بعته هو [cool-vacherin-09cd1d.netlify.app](https://cool-vacherin-09cd1d.netlify.app/). محاولة الوصول إليه من الويب والمتصفح لم تنجح وقت المراجعة؛ إعدادات المشروع وربطه بالمستودع وتشغيل الموقع عليه لم يتم التحقق منها. لذلك الرابط لسه مش نسخة عرض وظيفية تم اختبارها.

البناء النهائي واختبارات الكود نجحوا محليًا، بإجمالي ١٤١ حالة تحقق، منها ٣ تجارب HTTP فعلية لوظيفة إنهاء الامتحانات. ده يثبت تجهيز الكود المحلي؛ تجربة الدخول والصور والجدولة على رابط Netlify لسه خطوة باقية.

## تجهيز الدخول في الجلسة الجاية

افتح [لوحة Netlify](https://app.netlify.com/) على المشروع الموجود، و[لوحة مشروع Supabase المحدد](https://supabase.com/dashboard/project/soggnbfxawlwopglghas). المطور يتأكد من هوية المشروع والفرع، ثم يدخل إعدادات التشغيل ويكمل الاختبارات. لا نحتاج إنشاء مشروع Supabase جديد أو إعادة تطبيق migrations أو استيراد قاعدة الجهاز.

جهز اسم الأدمن ورقم الموبايل وكلمة سر خاصة بالتجربة. مفتاح Supabase السري وكلمة سر مستخدم قاعدة البيانات وأسرار التطبيق يدخلوا مباشرة في إعدادات Netlify أو مكان خاص مستبعد من Git أثناء التجهيز؛ متبعتهمش في الشات. [مفاتيح Supabase](https://supabase.com/docs/guides/getting-started/api-keys)، [متغيرات Netlify](https://docs.netlify.com/build/environment-variables/overview/).

## خطوات لوحة التحكم المتبقية

1. **Supabase → Authentication:** نراجع تفعيل Phone/password وإعداد Site URL. المسار الحالي بيأكد الهاتف إداريًا من السيرفر للتجربة، بدون إرسال SMS؛ نجاحه على المشروع السحابي لسه محتاج اختبار. [الدخول بكلمة السر](https://supabase.com/docs/guides/auth/passwords)، [إنشاء المستخدم من الإدارة](https://supabase.com/docs/reference/javascript/auth-admin-createuser)، [إعداد روابط Auth](https://supabase.com/docs/guides/auth/redirect-urls).
2. **Supabase → Connect:** نأخذ عنوان Transaction pooler الحقيقي، ونجهز كلمة سر `dorosna_server` بشكل خاص. إعداد الاتصال الإداري مختلف عن اتصال التطبيق.
3. **Supabase → Storage:** نجهز bucket خاصة باسم `dorosna-images` ونختبرها عبر السيرفر. الكود جاهز، لكن bucket والرفع الفعلي لم يُنفذا بعد. [إنشاء bucket](https://supabase.com/docs/guides/storage/buckets/creating-buckets).
4. **Netlify → Project configuration → Environment variables:** نضيف إعدادات نسخة العرض، ومنها `SUPABASE_IMAGE_BUCKET` و`APP_JOB_SECRET`، ثم نراجع Build وSSR والـAPI والدخول والصور على الرابط. [دعم Next.js](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/).
5. **جدولة الامتحانات:** نربط جدولة آمنة بـ`POST /api/internal/deadlines` ونجرب انتهاء الامتحان وإعادة المحاولة والتراكم. تجهيز endpoint وحده لا يشغل الجدولة. [Supabase Cron](https://supabase.com/docs/guides/cron/quickstart).

المطور يكمل إعدادات التشغيل والاختبارات دي على الموارد الموجودة. التفاصيل التقنية وحالة التحقق في [خطة نسخة العرض](PREVIEW-SETUP.ar.md)، ووصف الكتالوج في [دليل بيانات العرض](catalog-seed.ar.md).

شراء دومين أو خدمة SMS أو بريد مش مطلوب لمسار العرض الحالي. الفيديو الحقيقي له خطوة ربط منفصلة، وأي تفعيل لخدمة مدفوعة يتحدد قبل استخدامها. نسخة العرض للتجربة والاعتماد؛ تشغيل الطلاب يحتاج مراجعة الحمل وحدود الخدمات والمراقبة والاستعادة.
