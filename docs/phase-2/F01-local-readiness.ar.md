# F01 — تقرير جاهزية أدوات التجربة المحلية

تاريخ الفحص: **2026-10-02 بتوقيت القاهرة**.

**النتيجة: فحص الأدوات مكتمل؛ بيئة تجربة Supabase المحلية المقترحة غير جاهزة للتشغيل بعد.** Node.js وnpm موجودان، ولم تظهر Docker أو Supabase CLI في الأماكن المفحوصة. لم تنفذ تجربة الحسابات أو أي من اختبارات T01–T12 في [مقترح الحسابات](F01-auth-proposal.ar.md).

نطاق الإذن: فحص توفر وإصدارات Node.js وnpm وDocker وSupabase CLI، وفحص مؤشرات محرك Docker الموجود، وحفظ هذا التقرير. كل الأوامر كانت قراءة؛ لم يتم تثبيت أو تنزيل حزم، تعديل PATH، تشغيل خدمات أو حاويات، إنشاء مشروع سحابي، أو إدخال مفاتيح.

## 1. النتائج الفعلية

| الأداة | نتيجة الفحص | معناها للتجربة |
|---|---|---|
| Node.js المتاح في جلسة Codex | `v24.19.0`؛ استدعاء `node --version` نجح | يوجد runtime قابل للاستدعاء. هذه ليست نتيجة بناء أو اختبار توافق حزم التطبيق. |
| Node.js المثبت في Windows | `v22.19.0`؛ استدعاء الملف مباشرة نجح | يوجد تثبيت آخر منفصل عن runtime جلسة Codex. يلزم اختيار إصدار التشغيل صراحة عند تجهيز التجربة. |
| npm | `10.9.3`؛ نجح استدعاؤها من المسار المباشر، وكذلك تشغيل ملف CLI بواسطة Node الموجود في الجلسة | موجودة؛ `Get-Command npm` لم يجدها في PATH الحالي. لا يوجد سبب من هذا الفحص لإعادة تثبيت npm. |
| Docker CLI وDesktop | `Get-Command docker` لم يجد أمرًا؛ مسار Docker Desktop المعتاد غير موجود، ولم توجد executable في المواقع البديلة المفحوصة | لم أجد تثبيتًا متاحًا في نطاق البحث. لا يمكن تشغيل تجربة الحاويات باستخدام الأدوات الحالية المرئية. |
| محرك Docker | لم تظهر عملية `Docker Desktop` أو `com.docker.backend` أو `dockerd`، ولا خدمة `com.docker.service` أو `docker` | لم تظهر مؤشرات محرك يعمل. لم يجر اختبار اتصال daemon لغياب CLI؛ لم نحاول تشغيل محرك. |
| Supabase CLI | غير موجودة في PATH، أو `node_modules/.bin` بالمشروع، أو المواقع البديلة المفحوصة | تجهيزها يحتاج خطوة لاحقة معتمدة. لم ننفذ `npx` أو أي أمر قد ينزلها تلقائيًا. |

عدم العثور في PATH والأماكن المعتادة لا يثبت عدم وجود تثبيت في مكان مخصص آخر. النتائج تصف ما كان متاحًا في جلسة الفحص؛ لا يفترض أن PATH في terminal أخرى مطابق لهذه الجلسة.

يمكن في خطوة التنفيذ المعتمدة استخدام مسار npm الموجود صراحة بدل تغيير إعدادات الكمبيوتر لمجرد أن الأمر غير ظاهر. لم ننفذ تثبيتًا بهذا المسار، ولم نعتمد نسخة Node نهائية للمشروع.

## 3. نطاق البحث عن الأدوات الناقصة

فحص Docker شمل أمر PATH، وملف Desktop في `C:\Program Files\Docker\Docker\Docker Desktop.exe`، وروابط WinGet، وموقع Docker تحت برامج المستخدم، وScoop shims، وأسماء العمليات والخدمات المذكورة أعلاه.

فحص Supabase CLI شمل أمر PATH، و`node_modules\.bin\supabase.cmd` داخل المشروع، وروابط WinGet وScoop shims وموضع الأمر في مجلد npm للمستخدم. لم يوجد ملف مطابق في هذه المواقع.

لم يفحص هذا التقرير نسخة Windows أو RAM أو المعمارية أو دعم virtualization أو WSL2/Hyper-V. فحصها مع مراجعة المتطلبات الرسمية مقترح للخطوة التالية قبل اختيار طريقة تجهيز Docker. لم يتم فتح Docker Desktop أو إعداد WSL أو تعديل خصائص Windows.

## 4. أثر النتيجة على F01

- يمكن الاحتفاظ بترشيح الحسابات وخطة الاختبار للمراجعة؛ لا يوجد دليل عملي بعد على نجاح مسار الهاتف دون SMS في Supabase.
- تنفيذ التجربة المحلية المقترحة يحتاج توفير طريقة تشغيل الحاويات وCLI مناسبة، ثم إصدار SDK ثابت وبيانات اختبار. هذه الاحتياجات ليست تصريحًا بالتثبيت أو التشغيل.
- لا نعوض نقص Docker بإنشاء مشروع Supabase سحابي تلقائيًا. إنشاء خدمة خيار منفصل يحتاج موافقة المستخدم.
- ملفات التطبيق وschema وmigrations وfixtures لم تنشأ. لم يبدأ العمل في F02–F05 أو المراحل التالية.
- لا حاجة لإعداد Bunny أو دفع تكلفة فيديو ضمن تجربة الحسابات.

## 5. الخطوة التالية المقترحة للموافقة

**فحص متطلبات تجهيز Docker على هذا الجهاز، وقراءة توثيق Docker وSupabase CLI الرسمي، ثم حفظ خطة تثبيت محددة للمراجعة.** المجموعة المقترحة تشمل:

1. قراءة إصدار Windows والمعمارية والذاكرة ومؤشرات virtualization وإعدادات WSL/Hyper-V الموجودة، دون تشغيل توزيعة أو تفعيل أي ميزة.
2. مراجعة المتطلبات وطريقة تثبيت Docker وSupabase CLI المدعومة، وتحديد الإصدارات وطريقة استعمال Node/npm الموجودين دون تثبيت زائد.
3. تسجيل التنزيلات والتغييرات المطلوبة وما إذا كانت تحتاج صلاحيات أدمن أو إعادة تشغيل، ثم عرضها قبل التثبيت.

هذه المجموعة لم تُنفذ، وتنتظر الموافقة وفق طلب المستخدم السؤال قبل كل خطوة جديدة. أي تثبيت أو تنزيل أو تشغيل خدمة أو حاويات أو إعادة تشغيل يبقى خطوة لاحقة مستقلة.

مخرج هذه الدفعة ملف التقرير فقط. اقتراح الحسابات السابق وملفات المرحلة الأولى والتغييرات السابقة حُفظت دون تعديل.
