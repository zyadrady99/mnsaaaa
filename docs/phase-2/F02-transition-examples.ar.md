# F02 — أمثلة نجاح ورفض وانتقالات الوقت

هذه **أمثلة مراجعة للمواصفة، وليست اختبارات تشغيل منفذة**. تقابل المعرّفات في [عقد الحالات](F02-state-contract.ar.md). الهدف إعطاء F03 مثال نجاح ومثال رفض لكل فعل، مع أثر واضح على بقية الحالات؛ الاختبارات الفعلية تنفذ مع وظائف المنصة لاحقًا.

البيانات الوصفية: أدمن نشط، طالبان A وB، كورس C منشور وكورس D مسودة. نقطة الوقت `T = 2026-10-02T12:00:00Z`. أسماء الأكواد هنا مراجع رمزية فقط؛ لا أكواد قابلة للبيع أو حسابات حقيقية. في كل مثال تبدأ البيانات بحالة المثال مستقلة عن الأمثلة الأخرى.

## أمثلة كل انتقال

| المعرف | مثال نجاح | مثال رفض أو منع تكرار |
|---|---|---|
| A01 | A يقدم اسمًا وصفًا صالحًا وموبايلًا موحدًا وكلمة سر مقبولة؛ بعد اكتمال الهوية والملف يصبح طالبًا نشطًا واحدًا | حقل ناقص أو إرسال `role=admin` يرفض. صيغة أخرى لنفس الموبايل لا تنشئ هوية ثانية |
| A02 | الأدمن يعطل A لسبب مسجل؛ لا مشاهدة أو تفعيل أو بدء محاولة/حفظ إجابة. نهاية وصوله `2026-10-12T12:00Z` تبقى كما هي | B يحاول تعطيل A أو يتطلب الطلب ثقة بدور يرسله جسمه؛ لا تغيير. حذف الاشتراك كأثر للتعطيل ممنوع |
| A03 | الأدمن يعيد تفعيل A عند T؛ وصوله غير المسحوب المنتهي في 12 أكتوبر يصبح قابلًا للاستخدام لعشر أيام متبقية | وصول انتهى في 1 أكتوبر لا يعود بمجرد تنشيط الحساب. B لا يستطيع تنفيذ إعادة التفعيل |
| A04 | بعد تحقق حضوري، الأدمن يفتح استعادة لـA. تغيير الكلمة مرة واحدة ينهي القفل المؤقت ويترك حالته الأصلية | رقم الهاتف أو كود كورس فقط لا يكفي للاستعادة. إن كان A معطلًا فلا يتحول إلى نشط بسبب نجاح تغيير الكلمة |
| C01 | الأدمن يحفظ بيانات كورس جديد؛ المسودة تظهر له للإكمال | الطالب لا ينشئ كورسًا، ولا يجد المسودة في التصفح أو يصل لفيديوها بتغيير الرابط |
| C02 | بيانات C صحيحة وأول درس مختار للنشر له فيديو جاهز وتقييم صالح؛ ينشر الجزء الجاهز مع إبقاء درس مستقبل مسودة | فيديو الدرس المختار لا يزال قيد المعالجة أو التقييم ناقص؛ يبقى C مسودة وتظهر نواقصه للأدمن |
| C03 | الأدمن يؤرشف C؛ يختفي من الاكتشاف. A سبق أن فعله وله وصول حتى 12 أكتوبر، فيكمله حتى هذا الموعد | B يحاول تفعيل كود جديد لـC المؤرشف؛ يرفض ويبقى الكود غير مستخدم. لا يُفقد تقدم A |
| C04 | الأدمن يضيف درسًا جاهزًا في نهاية C وينشره؛ تقدم A في الدروس القديمة محفوظ | إدراج درس قبل درس مستخدم أو نشر درس بفيديو فاشل يرفض. حفظ مسودة جديدة لا يزيد عدد دروس تقدم الطالب |
| C05 | الأدمن يصحح عنوان درس مستخدم؛ معرف الدرس ودرجاته وموضعه وإكماله لا تتغير | تعديل «عنوان» مصحوب بحذف محتوى مستخدم أو تعديل أسئلة محاولة قديمة لا يعامل كتعديل شكلي |
| C06 | اختيار تنفيذ: الأدمن يرتب أو يحذف درس مسودة لم يُستخدم وليس له تقدم أو محاولة أو مرجع طالب | وجود أي استخدام يمنع حذف الدرس أو تغيير ترتيبه، حتى لو انتهى الاشتراك أو فُقد رد طلب الاستخدام |
| K01 | الأدمن يولد دفعة رمزية من 10 أكواد لـC مدة كل منها 30 يومًا؛ تكرار نفس الطلب يعيد دفعة الـ10 | مدة 45 يومًا أو عدد غير صالح يرفض؛ طلب الطالب لتوليد/تصدير دفعة يرفض. نفس طلب التوليد لا يضيف 10 أخرى |
| K02 | A يؤكد C، وكوده متاح وآخر تفعيله بعد T والكورس منشور؛ يستهلك الكود وينشئ وصول C له معًا | كود لـD أو ملغى أو متأخر أو حساب معطل: لا استهلاك ولا وصول. كود B من صفحة C لا يفتح C بصمت |
| K03 | الأدمن يلغي كودًا متاحًا؛ أي تفعيل تالٍ يرفض. إعادة الإلغاء تعيد الحالة النهائية نفسها | كود مستخدم لا يقبل الإلغاء لإعادته للبيع أو سحب وصول مالكه ضمن عملية الكود |
| K04 | بعد ضياع رد تفعيل A يعيد الكود المستخدم؛ يحصل على نتيجة تفعيله وحالة الوصول الحالية بلا إضافة أيام | B يعيد كود A فلا يحصل على وصول أو بيانات A. A يعيد كوده بعد سحب الوصول فلا يعود الوصول |
| E01 | K02 عند T لمدة 30 يومًا: البداية T والنهاية `2026-11-01T12:00:00Z`؛ يفتح الكورس C وحده | فشل إنشاء المنحة لا يترك الكود مستخدمًا. موعد نهاية مطبوع على الكود لا يصبح نهاية الوصول الجديد |
| E02 | وصول A ينتهي `2026-10-12T12:00Z`؛ يضيف كود 30 يومًا عند T، فتصبح النهاية `2026-11-11T12:00Z` | حساب النهاية من T يفقد عشرة أيام وهو مرفوض. إعادة نفس الكود لا تمدد إلى ديسمبر |
| E03 | انتهى الوصول في 1 أكتوبر؛ كود 30 يومًا عند T ينشئ نهاية 1 نوفمبر، مع بقاء التقدم والنتائج | تغيير الساعة على جهاز A أو تعديل تاريخ يرسله الطلب لا يزيد أيام المنحة |
| E04 | قبل `2026-11-01T12:00:00Z` بلحظة مسموح، وعند الموعد يرفض طلب تشغيل جديد ويبقى التاريخ | بقاء الصفحة مفتوحة أو حالة مخزنة لم تُحدّث إلى «منتهٍ» لا يسمح بطلب محمي بعد النهاية |
| E05 | الأدمن يسحب وصول A لـC بسبب مسجل؛ الفيديو ومحاولات جديدة/إجابات جديدة تتوقف والتاريخ يبقى | الطالب يسحب أو يمدد وصوله بنفسه، أو إجراء أدمن بلا سبب، يرفض. استعمال إلغاء الكود المستخدم بدل السحب يرفض |
| E06 | حساب A نشط وC منشور، وله كود جديد 30 يومًا عند T بعد السحب: ينشأ وصول جديد إلى 1 نوفمبر، وتبقى المنحة المسحوبة في السجل | الكود القديم أو حساب معطل أو C مؤرشف: لا عودة. تاريخ نهاية قديم في المنحة المسحوبة لا يضاف للمنحة الجديدة |
| E07 | الأدمن يمدد وصول A غير المسحوب خمسة أيام بسبب مسجل؛ نهاية 12 أكتوبر تصبح 17 أكتوبر. إذا كان A معطلًا يبقى معطلًا | تمديد بلا سبب أو بمدة سالبة يرفض. تعديل موعد سجل مسحوب لا يفك سحبه ضمن هذه العملية |
| M01 | A نشط ووصوله ساري والامتحان متاح ومحاولاته متبقية؛ يبدأ محاولة بموعد ونسخة ثابتين | حساب معطل أو وصول منتهٍ أو قفل واجب أو محاولات مستنفدة يمنع البدء. طلبان متكرران لا ينشئان محاولتين فعالتين |
| M02 | يصل تحديث إجابة بإصدار 2 قبل الموعد؛ يؤكد الخادم الحفظ. وصول تحديث قديم بإصدار 1 لا يستبدله | إجابة على الجهاز دون تأكيد لا توصف «تم الحفظ». تحديث بعد التسليم أو بعد الموعد أو من B يرفض |
| M03 | A يسلم الامتحان قبل الموعد؛ تحسب نتيجة واحدة من آخر إجابات الخادم، وغير المجاب صفر | تسليم لاحق لا يعدل الإجابات أو الدرجة. واجب ناقص لا يقبل التسليم النهائي وفق اختيار التنفيذ المقترح |
| M04 | محاولة لها موعد 12:30؛ عند الموعد تسلم إجابات الخادم ولو كان المتصفح مغلقًا أو الحساب عُطل بعد آخر حفظ | وصول إجابة محلية عند 12:30 أو بعدها لا يضيفها. تأخر عمل التسليم لا يفتح وقتًا إضافيًا للحفظ |
| M05 | بدأ الامتحان 11:50 بوصول ساري انتهى 12:00؛ A يستأنفه 12:10 حتى موعده الأصلي 12:30 | لا يبدأ محاولة ثانية أو فيديو جديد بعد 12:00. تعطيل الحساب أو سحب الوصول يمنع حفظ/استئناف الطالب، بخلاف انتهاء الاشتراك وحده |
| M06 | الأدمن ينشر أسئلة ودرجات معدلة كإصدار جديد؛ محاولة A الجارية تبقى على الإصدار القديم | تعديل نسخة محاولة A أو نتيجتها بصمت يرفض. رقم إصدار جديد لا يصفر عدد المحاولات المستهلكة تلقائيًا |
| L01 | A يضغط «خلصت الدرس» مرتين؛ يسجل إكمال واحد، وشريط التقدم يعده مرة | مجرد الوصول إلى موضع فيديو أو الضغط لدرس مقفول لا يثبت إكماله ولا يفتح التالي |
| L02 | A ينجح بدرجة فعلية 70% في الواجب السابق؛ يصبح التالي مفتوحًا مع استمرار شروط الوصول | 69% أو 69.9% أو تسليم بلا نجاح لا يفتح. فشل محاولة لاحقة لا يزيل نجاحًا سابقًا وفق اختيار التنفيذ المسجل |
| L03 | الأدمن يتجاوز قفل الواجب لدرس محدد عند A بسبب؛ يفتح هذا الدرس إذا بقية شروط الوصول متحققة | لا يفتح الدرس نفسه عند B أو كل الدروس، ولا يسمح لمستخدم معطل/منتهٍ، ولا يحول الدرجة إلى نجاح مزيف |
| V01 | يقبل مزود الاختبار رفعًا مرتبطًا بالدرس؛ ينتقل أصل الفيديو للمعالجة | مجرد اختيار ملف أو الحصول على معرف رفع ليس جاهزية؛ لا يسمح بنشر درس اعتمادًا عليه |
| V02 | نتيجة جاهزية مؤكدة للمحاولة الحالية تنقل الفيديو إلى جاهز | نتيجة قديمة أو مجهولة أو ملف محاكٍ في بيئة بيع لا تسمح بنشر الفيديو الحقيقي |
| V03 | المعالجة الحالية تبلغ فشلًا؛ يظهر سبب لإدارة المحتوى ويظل الدرس غير قابل للنشر | تحويل الفشل إلى جاهز يدويًا دون نتيجة مزود لا يعالج النقص |
| V04 | الأدمن يعيد محاولة المعالجة الفاشلة؛ تبقى هوية الدرس وتتبع المحاولة الجديدة | callback لمحاولة قديمة لا يغطي حالة الجديدة، وإعادة الطلب لا تنشئ درسًا مكررًا |

## الحدود الزمنية المحسوبة

| العملية | البداية/النهاية المدخلة | النتيجة المطلوبة |
|---|---|---|
| تفعيل 30 يومًا | T | `2026-11-01T12:00:00Z` |
| تفعيل 60 يومًا | T | `2026-12-01T12:00:00Z` |
| تفعيل 90 يومًا | T | `2026-12-31T12:00:00Z` |
| تجديد 30 مع عشرة أيام باقية | نهاية حالية `2026-10-12T12:00:00Z` | `2026-11-11T12:00:00Z` |
| تجديدان 30 و60 على وصول ساري | نهاية حالية `2026-10-12T12:00:00Z` | `2027-01-10T12:00:00Z`، بصرف النظر عن ترتيب الكودين |
| كود بعد سحب الوصول | نهاية منحة مسحوبة قديمة 12 أكتوبر، وتفعيل كود جديد عند T | `2026-11-01T12:00:00Z`؛ لا ترجع أيام المنحة المسحوبة |
| آخر تفعيل هو T | قبل T بلحظة، ثم عند T | الأول مؤهل إن بقية الشروط صالحة؛ الثاني مرفوض بلا استهلاك |
| امتحان نصف ساعة | بدء 11:50، ونهاية نافذة 12:10 | موعد 12:10 كاختيار تنفيذ؛ بلا نافذة يكون 12:20 |

تعرض المواعيد بتوقيت القاهرة، لكن لا تجمع الأيام بحسب شهر تقويمي أو ساعة جهاز الطالب. في F03 تتحقق العمليات من وقت الخادم عند اعتماد التغيير، وتنفذ اختبارات حدود النهاية فعليًا لاحقًا.

## مراجعة التزامن والحالات المركبة

| الحالة | النتيجة التي يجب أن يضمنها التنفيذ |
|---|---|
| A وB يؤكدان نفس الكود معًا | مالك واحد وتفعيل ومنحة واحدة. لا نجاح للكود مع خطأ إنشاء الوصول |
| الأدمن يلغي بينما A يفعّل | إن سبق الإلغاء فلا منحة والكود ملغى؛ إن سبق التفعيل فكود مستخدم مع منحة، والإلغاء يرفض |
| A يجدد بكودين مختلفين | كلا التفعيلين محفوظ مرة واحدة، ونهاية واحدة تساوي مجموع المدتين على الوصول السابق |
| فقد رد النجاح ثم إعادة الطلب | يرجع التفعيل النهائي نفسه؛ لا مدة إضافية، حتى لو انتهى الموعد أو أُرشف الكورس بعد التفعيل الأصلي |
| الأرشفة والتفعيل معًا | إذا سبق التفعيل ثبت وصول سابق يستمر؛ إذا سبقت الأرشفة لا استهلاك، ولا فحص حالة كورس قديم خارج الحد الذري |
| تعطيل ثم تجديد/حفظ/مشاهدة | العملية المعتمدة بعد التعطيل ترفض؛ تفعيل كود قديم ناجح يظل تاريخًا محفوظًا، لا حذفًا أو استرجاع أيام |
| سحب ثم كود جديد | الحساب النشط والكورس المنشور يسمحان E06. إعادة الكود القديم تعيد الحالة المسحوبة فقط |
| حساب معطل واشتراك ضمن مدته | الحالة الزمنية «ساري» لا تمنح عمليات. التنشيط لاحقًا لا يعيد ما مر من المدة ولا يفك سحب كورس |
| امتحان بدأ قبل انتهاء الاشتراك | الاستئناف والحفظ والتسليم قبل موعده مسموحة للحساب النشط؛ لا تمديد موعد ولا مشاهدة/محاولة جديدة |
| تسليم يدوي وتلقائي وإعادة طلب | نتيجة نهائية واحدة؛ إجابات الخادم التي اعتمدت قبل الحد الزمني فقط. الطلب اللاحق لا يعدلها |
| سجل إجابة أحدث يصل أولًا | تأكيد الإصدار الأحدث يظل ساريًا؛ القديم لا يمحو تقدمًا مؤكّدًا |
| حذف/ترتيب درس وبدء استخدامه | لا قبول تعديل اعتمادًا على قراءة قديمة «غير مستخدم» إذا ثبت استخدامه قبل اعتماد التعديل |
| نموذج امتحان واشتراك منتهٍ | قبل إتاحة النموذج لا مفاتيح في البيانات؛ بعد الإتاحة يستطيع صاحبه النشط قراءة إصدار نتيجته دون محاولة جديدة |
| نجاح الواجب ثم انتهاء الاشتراك | تحقق نجاح الدرس يظل محفوظًا، لكن لا مشاهدة حتى تجديد الوصول؛ الكود الجديد لا يصفّر التقدم |
| إضافة درس مسودة ثم نشره | قبل النشر لا يظهر أو يدخل مقام التقدم؛ بعد نشره قد تنخفض النسبة المعروضة، والإكمال القديم يبقى كما هو |

التحقق المنفذ لهذه الدفعة هو مراجعة اتساق المراجع وتغطية الانتقالات والحسابات الزمنية المكتوبة. لا SQLite أو Postgres أو mocks جديدة، ولا ادعاء باجتياز قبول الأكواد أو التقييمات أو الفيديو قبل بنائها.
