## المبادئ المفيدة للعمل الحالي

1. **اعتماد الشكل قبل تغيير الواجهة الأساسية:** معاينة منفصلة للكمبيوتر والموبايل، وبنسختي الضوء والدارك. تشمل الخط العربي والكروت والأزرار وحالات تحميل البيانات وفشلها. ده مناسب لطلب العميل الحالي، ومستفاد من مبادئ [مراجعة التصميم](https://github.com/garrytan/gstack/blob/main/plan-design-review/SKILL.md).
2. **تنظيف يخدم المشروع:** فصل مسؤوليات الملفات اللي محتاجة فصل، الحفاظ على المسارات والعقود الحالية، وتقسيم المهمة لأجزاء واضحة. نتجنب إعادة كتابة أجزاء مستقرة بدون سبب، وفق مبادئ [تنظيم التصميم في المشروع الموجود](https://github.com/obra/superpowers/blob/main/skills/brainstorming/SKILL.md).
3. **الإنجاز يحتاج دليل:** مراجعة الفروقات، ثم فحص الكود والبناء والاختبارات المناسبة للتغيير. تجربة رحلة الأدمن والطالب، وحالات الصلاحيات والموبايل، تكون قبل إعلان انتهاء مرحلة. [Superpowers](https://github.com/obra/superpowers/blob/main/skills/verification-before-completion/SKILL.md)، [gstack QA](https://github.com/garrytan/gstack/blob/main/qa/sections/qa-patterns.md).
4. **الكتابة واضحة وتحافظ على الحقائق:** الأزرار تسمي الفعل، الأخطاء تقول للمستخدم الخطوة التالية، والتقارير تعرض الحالة الفعلية. لا نضيف أرقامًا أو وعودًا في الصياغة بدون دليل. ده تطبيق لمبادئ [Humanizer](https://github.com/blader/humanizer/blob/main/SKILL.md) على النص العربي.

## حدود المراجعة

قرأنا README وملفات skills المرتبطة بالمقارنة عبر GitHub. لم نثبت المستودعات، ولم نشغّل سكربتاتها، ولم نرفع محتوى أو مفاتيح لخدماتها. المراجعة دي ليست فحصًا آليًا باستخدام SkillSpector.

تعليمات المستودعات مصادر للمقارنة؛ التثبيت وتغيير إعدادات Codex أو المتصفح والنشر والحسابات المدفوعة تظل خاضعة لتعليمات المشروع وطلب العميل. لا نضيف الأدوات الثمانية إلى dependencies الموقع: نختار الأداة وقت وجود مهمة فعلية تحتاجها.
